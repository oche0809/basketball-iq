## バスケ作戦盤の詳細

- 原本データ（公開資料）とチーム版（`data/team/team_tactics.json`）を分離する設計が既にある。**「原本」と「チームルール」を分ける考え方は IQ サイトでもそのまま採用する。**
- `verified: false` の内容は「資料確認中」と表示して動かさない、というルールがある。IQ サイトの「確認済み／要確認」の扱いもこれに合わせる。
- 戦術画面は `#/t/<戦術ID>`、守備ライブラリは `#/lib`。IQ サイトから **URL リンクだけで** 連携できる。
- 判断練習（`decisions`）・守備クイズ（`quizzes`）が既に作戦盤の中にある。IQ サイトとの役割分担：
  - 作戦盤＝**自チームの戦術の中での判断**（そのセットプレーのどこで何を見るか）
  - IQ サイト＝**戦術に依存しない、一般的な判断原則**（ヘルプが来たら空いた人を探す 等）

## 新規サイトの技術選定（提案）

**練習メニュー倉庫と同じ構成（React + Vite + TypeScript + Tailwind + ハッシュルーター + GitHub Actions）にする。**

理由：
1. すでに GitHub Pages への自動公開が動いている実績がある構成を再利用できる（ワークフローもほぼコピーで済む）。
2. 3つのサイトを将来1つの学習体系にまとめるとき、部品（コート描画・アニメーション）を共有しやすい。
3. 教材データ・画面・Coach Mode の編集画面など、画面数が多くなるので素の JS より保守しやすい。

追加するもの：`vitest`（単体テスト）、`ajv` または `zod`（教材JSONのチェック）、`@playwright/test`（スマホ幅での表示確認）。すべて無料。
