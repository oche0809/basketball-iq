# ④ MVP の最終仕様 ／ ⑤ 開発ロードマップ ／ 実装計画（PHASE 4・v2）

## 1. MVP の最終仕様（レビュー項目11）

### 1-1. 選手が体験する流れ

選手が、スマホで次の 7 ステップを **実際に体験できること** を MVP の完成とする。

| # | 体験 | 画面でやること | 使うデータ |
|---|---|---|---|
| 1 | 問題を見る | コート図・アニメーションが再生され、決めた位置で止まる | `court`・`stages[].show_until_step` |
| 2 | 何を見るべきか答える | 「最初に見るべきものは？」／「今、何が起きている？」に答える | `RECOGNITION` 段階 |
| 3 | 判断する | 「どうする？」／「何を優先する？」に答える（選択肢は毎回シャッフル） | `DECISION` 段階（CHOICE / PRIORITY） |
| 4 | なぜそうしたか答える | 理由を2つまで選ぶ（＋任意で一言） | `REASON` 段階 |
| （4'） | 相手の反応を見て次の判断 | 続きが再生され「DFが戻った。次は？」（一部の問題） | `REACTION` 段階 |
| 5 | 解説を見る | 続きを最後まで再生。全選択肢の「いつ有効か」、判断ルール、ルール枠（条文）と指導の原則を分けて表示、「相手が変えたら」 | `debrief`・`rule_notes`・`evidence` |
| 6 | 関連する練習を見る | 練習メニュー倉庫のメニューへのリンク（題名つき） | `related_drills`・`links_drills.json` |
| 7 | 自分の弱点を確認する | セットの最後に、手がかりごとの「見る力・判断力・理由」と、セットの「読めている／覚えている可能性」 | 回答記録（端末内） |

### 1-2. MVP に入れる機能・入れない機能

| 入れる | 入れない（後の段階） |
|---|---|
| HOME（今日のセット・続きから） | ログイン・サーバー保存 |
| PLAY：問題セット（intro → 2〜3問 → 振り返り）、レベル別、今日の課題（課題URL）、復習（理由が思い込みだった問題を優先） | 動画（VIDEO） |
| 段階：RECOGNITION / DECISION（CHOICE・PRIORITY）/ REASON / REACTION、位置をタップする問題 | ANTICIPATION 専用の画面、優先順位づけ（上位2つを並べる） |
| 判断の表示：この状況で優先／条件付きで有効／状況によっては有効／この状況では優先度が低い（記号なし） | COMPARE（自分の答え・基本・実際のプレー） |
| 診断（判断×理由）と MY IQ（手がかり別の3項目・セットの読めている度合い） | 回答の結果コード集計（先生側） |
| 解説のルール枠（条文番号）と指導の原則・チームの約束の印 | チームの約束の登録画面 |
| MAP：領域別一覧、手がかり図鑑、ルールカード | 問題作成エディタ |
| COACH（簡易）：教材一覧・確認状況・課題URLの発行 | オフライン（PWA） |
| GitHub Pages で公開 | AI |

### 1-3. MVP の教材

- **問題セット 8 つ（約 20〜24 問）＋単独の問題数問**。そのうち 4 セット・15 問は `data/sample_questions.json` に作成済み（先生確認前）。
- 追加する 4 セット：`SET-CLOSEOUT-READ`（DFが勢いあり／構えている／遅れた）、`SET-CUT-READ`（DFがボールを見る／ディナイ／離れて守る）、`SET-OFFBALL-POSITION`（1パス／2パス／パスが出た）、`SET-3V2`（上のDFが来る／来ない）。
- **公開するのは先生が確認した問題（`coach_reviewed` 以上）だけ**。確認前の問題は「確認中」と表示するか、非表示にする。
- チームの約束が必要な問題（`needs_team_rule`）は、約束を登録するまで公開しない。

### 1-4. MVP の完了条件

1. iPhone（Safari）で公開URLを開き、課題URLから問題セットを1つ最後まで解ける（7ステップすべて）。
2. 同じセットの中で、DF（または時計）だけが違い、最優先の判断が変わることを体験できる。
3. 「答えは合っているが理由が思い込み」の時に、そう表示され、同じセットの別の問題が復習に入る。
4. MY IQ に、手がかりごとの見る力・判断力・理由が分かれて表示される。
5. 1回の学習（セット1つ＋復習）が、試した生徒で **5〜10分** に収まる（収まらなければ問題の段階数を調整）。
6. 教材データチェックとテストに失敗すると公開されない。

## 3. 実装計画（段階1 = MVP）

共通ルール：各 STEP の終わりに **テスト → ビルド → スマホ幅（375px）の画面確認**。練習メニュー倉庫・作戦盤のファイルは **一切変更しない**（読み取りとリンクのみ）。

### STEP 1　土台づくり
- **作業内容**：Vite + React + TypeScript + Tailwind の骨組み、ハッシュルーター、下部タブ（HOME / PLAY / MAP / MY IQ）、`setup.sh`・`run.sh`、vitest・Playwright。
- **変更ファイル**：なし（新規プロジェクト）。`docs/`・`data/` はそのまま残す。
- **新規ファイル**：`package.json`、`vite.config.ts`（`base: '/basketball-iq/'`）、`tsconfig*.json`、`index.html`、`src/main.tsx`、`src/App.tsx`、`src/utils/router.ts`、`src/components/TabBar.tsx`、`setup.sh`、`run.sh`、`.gitignore`、`vitest.config.ts`、`playwright.config.ts`
- **実装理由**：練習メニュー倉庫で公開実績のある構成に合わせる。
- **完了条件**：`./setup.sh` → `./run.sh` で HOME が出る。`npm run build` が通る。
- **テスト内容**：ビルド、ルーターの単体テスト、375px・1280px で横スクロールなし。

### STEP 2　教材データの仕組み（v2 スキーマとデータチェック）
- **作業内容**：v2 の型定義。今回の一時スクリプトの内容をデータチェックとして正式に実装（`02_design.md` 15章の全項目）。`data/` → `content/`（1問1ファイル）へ移し、`public/data/`（一覧＋1問1ファイル）を生成。
- **変更ファイル**：`package.json`（`check`・`build:content` スクリプト）
- **新規ファイル**：`src/types/content.ts`、`scripts/validate-content.ts`、`scripts/build-content.ts`、`content/questions/**/*.json`（15問）、`content/question_sets.json`、`content/{cues,rules,sources,curriculum}.json`、`content/links/drills.json`、`tests/validate-content.test.ts`、`tests/fixtures/bad-*.json`
- **実装理由**：1000問に増えても壊れない。暗記で解けるセット・根拠の混同・段階の抜けを公開前に止める。
- **完了条件**：15問・4セットが通る。わざと壊したデータ（今回確認した5パターン＋参照切れ・座標範囲外・ID重複）を **すべてエラーにできる**。
- **テスト内容**：データチェックの単体テスト（正常1件＋異常パターンごとに1件）。

### STEP 3　コート図とアニメーション（段階ごとに止める）
- **作業内容**：SVG ハーフコート（ミドルライン表示の切り替え）、選手（OF＝塗り＋番号、DF＝白抜き、YOU＝強調）、動き・パス・シュート、**段階ごとの `show_until_step` で止めて続きを再生**、「もう一度見る」、HUD（時計・点差）、位置をタップする問題（SPOT）。
- **変更ファイル**：なし
- **新規ファイル**：`src/court/Court.tsx`、`src/court/Player.tsx`、`src/court/animation.ts`、`src/court/geometry.ts`、`src/court/SpotPicker.tsx`、`tests/animation.test.ts`
- **実装理由**：「読む」より「見て考える」の中心部品。座標は練習メニュー倉庫と同じ形式（倉庫のコードはコピーせず、同じ形式で新しく書く）。
- **完了条件**：15問のコート図が表示され、各段階の位置で止まり、続きが再生される。
- **テスト内容**：止まる位置・ボールの持ち主の移り変わりの単体テスト、Playwright で各問を 375px で確認。

### STEP 4　問題画面（見る → 判断 → なぜ → 相手の反応 → 解説）
- **作業内容**：段階の順番どおりに表示する問題画面。見る問いの一言フィードバック、判断の選択肢のシャッフル、理由（2つまで＋任意の一言）、REACTION、解説（全選択肢の「いつ有効か」、判断ルール、ルール枠と指導の原則の印）、関連練習（`https://oche0809.github.io/basketball-menu-warehouse/#/menus/lib-060` の形）、確認中バッジ。
- **変更ファイル**：なし
- **新規ファイル**：`src/question/QuestionFlow.tsx`、`src/question/stages/{Recognition,Decision,Reason,Reaction}.tsx`、`src/question/Debrief.tsx`、`src/question/EvidenceBadge.tsx`、`src/utils/grading.ts`（段階ごとの採点と診断）、`tests/grading.test.ts`、`e2e/question-flow.spec.ts`
- **実装理由**：見る・判断・理由を別々に記録し、「答えは合っているが理由が違う」を返せるようにする。
- **完了条件**：15問すべてを最後まで解ける。診断（`02_design.md` 3-3 の表）がすべての組み合わせで正しく出る。
- **テスト内容**：診断の単体テスト（判断4種×理由4種＋理由と判断の不一致）、Playwright で CHOICE・PRIORITY・SPOT・REACTION を1問ずつ（375px）。
- **確認が必要な点**：練習メニュー倉庫のメニューは各端末のブラウザに取り込まれて表示される仕組みのため、リンク先で開けるかを実機で確認する（開けない場合は題名表示だけにする）。

### STEP 5　問題セットと PLAY
- **作業内容**：セットの流れ（intro → 問題 → 振り返りの問い → セットの評価）、順番（fixed / shuffle）、今日のセット（日付で決まる）、課題URL（`#/set?ids=…`）、段階ごとの保存と再開、復習リスト（理由が思い込み・無関係だった問題を優先）。
- **変更ファイル**：`src/App.tsx`
- **新規ファイル**：`src/pages/PlayPage.tsx`、`src/pages/SetPage.tsx`、`src/store/attempts.ts`（localStorage・try/catch つき、将来サーバーに差し替え可能）、`src/utils/{daily,assignment,review,setMastery}.ts`、各テスト
- **実装理由**：「同じ状況で相手だけ変わる」を連続で体験させる。毎日 5〜10 分使えるようにする。
- **完了条件**：課題URLからセットを最後まで解ける。途中で閉じても続きから再開できる。保存できない環境でも解ける。
- **テスト内容**：セットの評価（全問／一部）、今日のセットが同じ日なら同じ、課題URLの作成⇄読み取り、保存失敗時に止まらない。**生徒（数名）に試してもらい、1回の学習時間を測る**。

### STEP 6　MY IQ と MAP
- **作業内容**：手がかりごとの見る力・判断力・理由、セットの「読めている／覚えている可能性」、自分の「なぜ？」の記録。MAP：領域別一覧、手がかり図鑑、ルールカード（`rules.json` から）。
- **変更ファイル**：`src/App.tsx`
- **新規ファイル**：`src/pages/MyIqPage.tsx`、`src/pages/MapPage.tsx`、`src/utils/mastery.ts`、`tests/mastery.test.ts`
- **実装理由**：弱点が「見えていない」のか「選べていない」のか「理由が思い込み」なのかを、選手自身が分かるようにする。
- **完了条件**：数セット解くと、手がかりごとに3項目が分かれて表示される（3回未満の手がかりは判定しない）。
- **テスト内容**：集計の単体テスト（見る問いを外した時に見る力へ加点しない、など）。

### STEP 7　COACH（簡易版）
- **作業内容**：`#/coach` に教材一覧（領域・難易度・学年・確認状況・チームの約束が必要か で絞り込み）、セットや問題を選んで課題URLを発行（コピー・QRコード）。
- **変更ファイル**：`src/App.tsx`
- **新規ファイル**：`src/pages/coach/CoachHome.tsx`、`src/pages/coach/AssignmentBuilder.tsx`、`e2e/coach.spec.ts`
- **実装理由**：先生が「今日の課題」をすぐ配れるようにする。
- **完了条件**：先生が PC でセットを選び、発行したURLをスマホで開くとそのセットが出る。
- **テスト内容**：Playwright で「選ぶ → URL 発行 → 開く → セットが出る」。

### STEP 8　MVP の教材をそろえる（データの作業）
- **作業内容**：1-3 の追加 4 セットを作る。全問を先生に確認してもらい、`coach_reviewed` にする。チームの約束（戻る時の優先・ローテーションの担当など）を聞いて反映。
- **変更ファイル**：`content/questions/**`、`content/question_sets.json`
- **新規ファイル**：追加の問題 JSON（約 8〜10 問）
- **実装理由**：MVP の完了条件（セット8つ）を満たす。内容の正しさは先生の確認で担保する。
- **完了条件**：データチェックが通り、公開対象の全問が `coach_reviewed` 以上。
- **テスト内容**：データチェック、Playwright で全セットを1回ずつ解く。

### STEP 9　公開（GitHub Pages）
- **作業内容**：Actions のワークフロー（テスト → 教材データチェック → ビルド → 公開）。GitHub のリポジトリ作成と Pages の設定。
- **新規ファイル**：`.github/workflows/deploy.yml`、`README.md`（更新）
- **完了条件**：公開URLを iPhone で開き、1-4 の完了条件をすべて満たす。
- **テスト内容**：Actions が緑、公開URLで Playwright（375px）。
- **先生の操作が必要**：GitHub でのリポジトリ作成・Pages 設定（その時に手順とコマンドを示す）、リポジトリを公開にするかの判断。
